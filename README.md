# Product Management API

REST API developed in ASP.NET Core for managing products and stocks.

The application was developed using .NET 10, Entity Framework Core and SQL Server, following a layered architecture to separate API, business logic, data access and persistence concerns.

## Technologies

- .NET 10
- ASP.NET Core Web API
- Entity Framework Core
- SQL Server
- Swagger / OpenAPI

## Project Structure

The solution is divided into the following projects:

- `ProductManagement.API` - REST API, controllers and application configuration.
- `ProductManagement.Business` - Business logic and business models.
- `ProductManagement.DataAccess` - Repository layer and database operations.
- `ProductManagement.Data` - Entity Framework Core context, entities and migrations.
- `ProductManagement.Common` - Shared models, enums and settings.
- `ProductManagement.Tests` - Unit tests.

## Requirements

To run the application locally, the following are required:

- .NET 10 SDK
- SQL Server

## Database Configuration

For security reasons, database credentials are not stored in the repository.

Configure the SQL Server connection string using .NET User Secrets from the API project directory:

```bash
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=localhost;Database=ProductManagement;User Id=YOUR_USER;Password=YOUR_PASSWORD;TrustServerCertificate=True;"
```

Alternatively, the connection string can be provided through the following environment variable:

```text
ConnectionStrings__DefaultConnection
```

## Running the Application

Restore the dependencies:

```bash
dotnet restore
```

Run the API:

```bash
dotnet run --project ProductManagement.API
```

On application startup, pending Entity Framework Core migrations are automatically applied and the initial product data is seeded when required.

Swagger is available when the application is running and can be used to explore and test all API endpoints.

## Product IDs

Product IDs are automatically generated by SQL Server using a database sequence.

The sequence generates unique six-digit identifiers in the range:

```text
100000 - 999999
```

Generating the identifier at database level avoids application-side random ID generation and guarantees uniqueness when multiple instances of the API are running concurrently.

## Database Migrations

Entity Framework Core migrations are included in the repository.

To create a new migration:

```bash
dotnet ef migrations add MigrationName --project ProductManagement.Data --startup-project ProductManagement.API
```

To manually update the database:

```bash
dotnet ef database update --project ProductManagement.Data --startup-project ProductManagement.API
```

The application also applies pending migrations automatically during startup.

## Design Decisions

The solution uses a layered architecture to keep responsibilities separated and improve maintainability and testability.

Some relevant implementation decisions are:

- SQL Server sequence for distributed-safe six-digit product ID generation.
- Repository pattern to isolate data access.
- Business layer separated from the API layer.
- DTOs used at the API boundary.
- Atomic stock updates to prevent race conditions.
- Database credentials excluded from source control.
- Entity Framework Core migrations for database versioning.
- Asynchronous database operations throughout the application.
